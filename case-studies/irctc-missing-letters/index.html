The Missing Letters: Investigating Passenger Name Inconsistency in IRCTC Ticket Booking

A real-world UX investigation and conceptual mobile redesign examining how a verified passenger name saved in full inside the IRCTC Passenger Master List appeared shortened on the generated Electronic Reservation Slip (ERS).

Role Gourishetti Shirisha • UI/UX Designer
Project Type Independent UX Observation & Conceptual Redesign
Platform Mobile-First Ticket Booking Experience
Design Status Proposed Concept (Unimplemented / Untested)
Section 01

Project Overview

Product Context: IRCTC (Indian Railway Catering and Tourism Corporation) serves millions of rail travellers across India. To streamline repeat reservations, the mobile booking experience offers a Passenger Master List where users store traveller details—including full name, date of birth, gender, berth/catering preferences, and Aadhaar verification status—for reuse during ticket booking.

Problem Summary: During a live ticket booking flow, a passenger profile saved and verified in the Master List under the full name PRIYANKA CHAKRABORTY was selected for travel. However, upon ticket generation, the Electronic Reservation Slip (ERS) printed the passenger's name as PRIYANKA CHAKRAB—omitting the final four characters (ORTY) without any pre-booking alert or explanation. Because Indian Railways mandates carrying prescribed original photo ID proof matching ticket details during travel, silent name shortening introduces friction and passenger anxiety.

Scope & Integrity Note: All observations in this study are grounded strictly in two primary artifacts from a real booking session (the Passenger Master List screen and the generated ERS). Personal names, dates of birth, and PNR details have been anonymized for privacy while preserving exact character lengths (20 characters vs. 16 characters). No user interviews, usability tests, analytics, or unverified technical root causes are fabricated.

Observed Facts vs. Investigative Technical Hypotheses

Confirmed Visual Facts (From Screenshots)

  • The Master List displays PRIYANKA CHAKRABORTY in full alongside a green check icon and "Verified - Passenger is aadhaar verified."
  • The generated ERS displays PRIYANKA CHAKRAB in the Passenger Details table while retaining accurate age (34), gender (F), meal option (VEG), and seat status.
  • No warning message indicates that the name was shortened between selection and ticket generation.

Possible Technical Explanations (Unconfirmed)

  • Character Length Caps: Downstream reservation or ERS rendering fields may enforce a 16-character limit not reflected in the Master List UI.
  • String Truncation: Fixed-width clipping during payload serialization or PDF/ERS template generation.
  • Schema / Data Mapping Differences: Legacy passenger chart fields mapping differently from newer Master List profile storage.
  • Backend Formatting Rules: Automated string parsing or formatting transformations applied during ticketing.

Important Boundary: While Aadhaar verification status is visible on the Master List entry, Aadhaar authentication is not claimed or assumed to be the technical cause of the name truncation.

Section 04

UX Problem Analysis & Heuristic Evaluation

Evaluating the observed workflow against Nielsen's Usability Heuristics highlights how a data-rendering gap directly impacts user expectations, error prevention, and trust.

Heuristic #4

Consistency and Standards

Data Consistency: The same passenger entity is represented as PRIYANKA CHAKRABORTY in profile management and PRIYANKA CHAKRAB on the ticket output, violating cross-screen consistency.

Heuristic #2

Match Between System & Real World

User Expectations: Travellers expect a verified profile name to match their real-world government ID on official travel documents without silent abbreviation.

Heuristic #5

Error Prevention

Passenger Identity Accuracy: No pre-booking check warns the user that the ticket name differs from the Master List name before payment is finalized.

Heuristic #1

Visibility of System Status

Booking Confirmation Experience: While Aadhaar verification is clearly surfaced, the system never communicates downstream character limits or name modifications.

Trust & Assurance

User Trust

When a "Verified" badge is followed by a truncated name on a paid ticket, users lose confidence in whether their identity data is preserved reliably.

Travel Compliance

On-Board Verification Risk

The ERS explicitly states that prescribed original ID proof is required during travel. A four-letter omission invites scrutiny during ticket inspection.

Section 08

Screen-by-Screen Design Rationale

Screen What Changed? Why Was It Changed? User Problem Solved Experience Improvement
1. Add Passenger Added explicit ID-matching instructions, structured labels, and real-time full-name confirmation. Users need clarity at entry that full names are captured completely for travel records. Eliminates uncertainty around whether longer names are accepted intact. Establishes a clean, verifiable source of truth from initial setup.
2. Passenger Master List Grouped passenger metadata into scannable cards with distinct verification status pills and clear Edit actions. Dense text rows with mixed icon styles slow down verification checks during booking. Makes it effortless to verify passenger name accuracy and Aadhaar status at a glance. Improves visual hierarchy, readability, and confidence in saved profiles.
3. Passenger Selection Added clear selection states, full unclipped passenger names, verification badges, and inline Edit controls. Selecting a traveller should confirm complete identity details before proceeding. Prevents accidental booking with unverified or incomplete passenger records. Streamlines passenger selection with transparent identity cues.
4. Passenger Details Review Introduced a dedicated pre-payment review card displaying full name, demographics, and profile match status. Skipping straight to payment hides potential data discrepancies until after ticketing. Gives travellers a deliberate checkpoint to catch identity errors before paying. Shifts error detection from reactive post-booking to proactive review.
5. Booking Confirmation Added a Ticket Name Verification module comparing saved profile name vs. ticket output name, plus a mismatch alert state. Resolving a shortened name before ticket issuance avoids post-booking stress. Prevents silent truncation (PRIYANKA CHAKRAB) from reaching final issuance unnoticed. Builds strong transactional trust via visible pre-confirmation safeguards.
6. Final Ticket Preview Elevated full passenger name prominence alongside PNR, seat status, verification badge, and ID-proof guidance. The ERS is inspected during travel and must align clearly with the traveller's physical/digital ID. Eliminates confusion caused by missing letters on the generated ERS. Delivers a cohesive, legible, and trustworthy travel document.

Section 11

Final Learnings & Product Design Takeaways

  • Observing Real-World Usability Problems: Everyday transactional flows often conceal edge-case friction—such as longer passenger names—that only surfaces when comparing profile storage against real document outputs.
  • Bridging Expectations and System Behaviour: Users treat a saved, verified profile as an authoritative record. Any silent discrepancy between stored data and printed output erodes confidence.
  • UX and Data Integrity Work Together: Great UI design cannot replace backend data consistency, but transparent field validation, review checkpoints, and status indicators expose and prevent integrity gaps before they affect users.
  • Preventive Design Over Reactive Friction: Catching a potential name mismatch before payment eliminates travel-day anxiety far more effectively than post-booking explanations.
  • Designing for Trust in High-Stakes Workflows: In rail ticketing, where identity verification directly governs boarding compliance, clarity and consistency are foundational to user trust.

Product Design • Mobile UX • Data Consistency

Ever saved your full name in a booking profile, only to see the last few letters disappear on your final ticket? 🚆

While booking a train ticket on IRCTC, I noticed a subtle but high-stakes UX & data consistency gap: a passenger profile saved in the Master List as PRIYANKA CHAKRABORTY (with Aadhaar status showing Verified) was printed as PRIYANKA CHAKRAB on the generated Electronic Reservation Slip (ERS).

Because rail travel requires carrying valid government ID proof matching ticket details, even four missing letters can create unnecessary friction and anxiety for passengers. Rather than guessing a single backend cause—whether character limits, string truncation, or data-mapping rules—I focused on the user-facing gap: there is no pre-booking checkpoint validating that the ticket name matches the saved profile before payment.

In my new case study, The Missing Letters, I document the real-world evidence, evaluate the flow using Nielsen's usability heuristics, and propose six mobile UI concepts—introducing a dedicated Passenger Details Review step and a pre-payment Ticket Name Check to catch mismatches before confirmation. (Conceptual redesign; not affiliated with or implemented by IRCTC.)
